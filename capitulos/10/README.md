# Capítulo 10. Gestión de errores y excepciones: del fallo local a la respuesta del sistema

[← Índice del repositorio](../../README.md) · [Libro gratuito: lectura en línea y PDF versionado](https://miraut.github.io/libro_MISRA_CPP_2023/)

## El problema que estudiamos

Un destructor intenta registrar un diagnóstico mientras se está tratando un error. Si esa operación propaga otra excepción, la ejecución puede terminar de forma inesperada.

Este capítulo del libro explica **excepciones, garantías de estado, `noexcept`, captura, terminación y resultados tipados.**. Los archivos de esta carpeta permiten seguir el razonamiento con código real: observar la construcción que plantea la dificultad, estudiar una alternativa y comprobar las hipótesis que hacen válida una solución. La explicación del libro proporciona el contexto necesario para interpretar cada fragmento.

## Qué puedes aprender con este código

Los archivos `E01.cpp` a `E15.cpp` recorren las decisiones de comunicación y recuperación de errores. Para cada caso, identifica el estado del componente después de una operación fallida y qué conoce su llamador.

La lectura resulta más útil si, antes de consultar la solución, intentas responder a dos preguntas: **¿qué garantiza C++17 en este punto?** y **¿qué propiedad adicional necesitamos justificar para el sistema?** Las respuestas pueden depender de la plataforma, de las condiciones de entrada o de reglas MISRA que se estudian conjuntamente.

## Cómo comprobar los ejemplos

La carpeta contiene ejemplos, sin pruebas ni scripts. Los escenarios de terminación abrupta se estudian por lectura y compilación selectiva, evitando ejecutarlos como demostración ordinaria.

Para un fragmento **autónomo, identificado previamente como seguro y compilable**, una primera comprobación puede ser:

```sh
g++ -std=c++17 -Wall -Wextra -Wpedantic -pedantic-errors -c ejemplos/ARCHIVO.cpp
```

Sustituye `ARCHIVO.cpp` por un nombre existente en `ejemplos/`. Esta orden solo comprueba la traducción del archivo, no su comportamiento durante la ejecución. Para casos con cabeceras, bibliotecas, opciones de preprocesador o varias unidades de traducción, sigue las instrucciones específicas anteriores y el contexto del capítulo. Comprueba también qué compiladores y herramientas están instalados antes de utilizar scripts.

> **Antes de ejecutar:** `noexcept` no significa que la función esté libre de fallos: una excepción que escape de ella puede provocar `std::terminate`. Los ejemplos intencionadamente incorrectos pueden servir para examinar un diagnóstico o un rechazo del compilador, pero no deben ejecutarse para provocar comportamiento indefinido. Una compilación correcta, una prueba funcional satisfactoria o la ausencia de advertencias no constituyen por sí solas una declaración de conformidad con MISRA C++:2023.
